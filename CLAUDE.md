## Project overview

A personal career portfolio for Vishvanath Patil (Senior Cloud Engineer). Pure static HTML/CSS/JS — **no server, no build step, no dependencies, no tests, no linting**. All assets are local with relative paths so the site works off `file://` and GitHub Pages identically.

## Commands

There is no build, test, or lint toolchain. To develop:

- Preview locally: double-click `index.html`, or `python -m http.server` from the repo root for a nicer preview.
- Regenerate the placeholder resume PDF: `python3 tools/make_resume_pdf.py` (stdlib-only, writes `assets/resume/Resume.pdf`).
- Deploy: push to GitHub Pages (repo `Vishvanath-Patil/My-Project`, branch `master`, source `/ (root)`). See README §2.

## Architecture

**Five standalone HTML pages** at the repo root — each is a complete, self-contained document. There is no templating or shared partial: the header nav, footer, theme toggle, and social bars are **duplicated by hand in every page** (`index.html`, `resume.html`, `products.html`, `contact.html`, `404.html`). When changing nav/footer markup, update all pages.

**One config-driven JS file** — `assets/js/site.js`, loaded at the end of `<body>` on every page. Its `DOMContentLoaded` init (`renderSocials`, `feedPage`, `setupTheme`, `setupNav`, `setupYear`) fills in elements marked with hooks. Rules for wiring widgets:

- `data-socials` (on a `<ul class="socials">`) → `renderSocials()` injects the social icon list. `data-socials="mail"` also appends the mail icon; other pages just `data-socials`.
- `data-brand-name` → `feedPage()` sets brand text in nav + footer.
- IDs `themeToggle`, `navToggle`, `navMenu`, `year` are wired by `setupTheme`/`setupNav`/`setupYear` and must stay unique per page.

**Single edit point for personal data.** `siteConfig` (name, role, email, social URLs, stats) and the `experience` array (both in `site.js`) drive socials, footer, contact links, and the experience sections. Personal details should be changed in `site.js`, not by editing duplicated text in the HTML — though the hero/about/experience text on `index.html` and `resume.html` is static HTML that must be updated by hand to match `site.js`.

**Theme system** — `style.css` defines light theme tokens on `:root`; `[data-theme="dark"]` overrides them. `setupTheme()` sets the `data-theme` attribute on `<html>` from `localStorage`, falling back to `prefers-color-scheme`. Any new UI must use the CSS variables and work under both themes.

**Print styling** — `@media print` block in `style.css` hides the nav/toolbar; `resume.html` has a Print/Save-as-PDF button (`window.print()`) and is the styled source of truth for the resume.

## Content consistency caveats

- The resume exists in three forms that must stay in sync: `resume.html` (source of truth), `assets/resume/Resume.pdf` (a placeholder generated by `tools/make_resume_pdf.py`, overwritten with the real PDF for deployment), and the contact email in `assets/js/site.js`.
- `contact.html` has an inline `sendContact()` script placed *before* `site.js` — it reads `siteConfig.email` lazily inside the function, so load order doesn't matter, but keep it that way.
- `robots.txt` disallows `/*.html?print=true` and `/assets/resume/` from search indexing; the print param is used by some browsers when saving resume.html as PDF.
- GitHub Pages serves the repo at `https://Vishvanath-Patil.github.io/My-Project/`, so all internal links/forms must use **repo-relative paths** (e.g. `products.html`, `assets/...`), never `/...` root-absolute — that would break the subdirectory deployment. `index.html` at repo root is the landing page.
